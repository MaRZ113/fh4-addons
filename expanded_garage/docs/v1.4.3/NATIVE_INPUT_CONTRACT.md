# Native input contract

The upstream producer is terrain presentation. Its 48-byte input carries two signed 32-bit horizontal center coordinates at `+0/+4`, a view-direction vector at `+0x10` and a motion vector at `+0x20`. The native code multiplies the blended world-space X/Z values by the same single-precision constant, `255.75`, before converting to integers. This applies to track/world axes and is separate from Carbin's body-local positions and texture UVs. It is not an asset-space conversion.

`RBX+0x120/+0x128` are alternate horizontal focus components in floats. The instructions at `0x4680FE5/0x4680FE9` use them only while the override counter is active and the ring meets the level threshold. XMM7 is the same `255.75` scale. XMM3 and XMM4 are an optional horizontal offset derived from filtered view direction and the ring level. The `0x4680FFD/0x4681003` conversions add those deltas to the base center. The capture shows the override counter at zero where the bad base center is present. This rules out those alternate conversions as the origin of the recorded `INT_MIN` base pair.

The captured focus translation has quiet NaN bit patterns. The SDK-equivalent arithmetic yields the SSE integer-indefinite value `0x80000000`. An exact finite signed minimum can have the same integer bits, so the full chain relies on the captured float values. The first ring's `2048`-unit extent explains the observed signed wrap: `int32(INT_MIN - 1024) = 2147482624`. The downstream grid spans tile coordinates `−24..23`.

The initial physics contract requires a finite world pose and velocity before first publication. At the captured Suzuki interface, the Y components of world position and velocity are NaN. The body origin X/Z, the parked camera basis and the active control's pose immediately before focus change were finite. The prior successful 3477 and 422 previews establish healthy outputs for the same interaction. This handoff contains no new sampled physics state for those two cars.
