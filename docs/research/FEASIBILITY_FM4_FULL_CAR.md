# Новый CarID с полной геометрией FM4: оценка реализуемости

Дата: 2026-11-19. Установка FH4 Steam 1.478.564.0 находится в состоянии Phase 2: хэши ZIP `a4156136…`, GameDB `dc470e01…` и манифеста `eb086ab0…` совпадают с эталоном. Источник: FM4 CarID 370 `HON_IntegraR_00` (DC2), уже извлечён в `.scratch/phase3_1/fm4/extracted/hon_dc2_00`.

## Вывод

| Вариант | Статус |
|---|---|
| A. Отдельный MediaName/архив: свой скелет, локаторы, свет, физика, звук и Forzavista | **Сейчас недостижим.** Phase 3: Null Car и зависание. Причину отказа на стороне движка не установили. |
| B. Общий архив Acura `ACU_IntegraR_01`, где 3477 получает по ID свой набор Modelbin | **Технически реализуем, но в игре не проверен.** Есть прецедент в стоковых данных FH4, а цепочка инструментов доступна. Безопасен только как поэтапный эксперимент с откатом. |

Полностью независимую машину, у которой всё своё и донор 368 не затронут, сейчас сделать **нельзя**. Можно получить 3477 с кузовом, бамперами, капотом, порогами, крылом и стёклами Honda. Скелет, локаторы, свет, коллизия, анимации, IK водителя и колёса при этом останутся от Acura.

## Новое доказательство: кузов может выбираться по ID

Скан всех 784 Carbin в `media/cars` (`Shared.zip` содержит несколько Carbin и в скан не вошёл):

| Тип группы | Апгрейдная (по ID) | Фиксированная |
|---|---:|---:|
| 2: кузов, платформа, салон, стёкла, двери | 76 машин | 707 |
| 34: передний бампер | 659 | 89 |
| 35: задний бампер | 216 | 430 |
| 36: капот | 215 | 429 |
| 37: пороги | 169 | 257 |
| 9: антикрыло | 650 | 68 |
| 4: тормоза | 0 | 763 |
| 43: колёса | 0 | 783 |

В 76 стоковых машинах (например `AUD_RS6_15`, `NIS_SilviaSpecR_00`, `HON_S2000_03`) группа type 2 апгрейдная. ID её узлов равны `List_UpgradeCarBody.Id`, у узлов parent = -1, а все около 75 моделей кузова лежат в shared-списках с явным перечислением ID. У RS6, например, 75 моделей с ID `{2180000, 2180100}` и 4 модели только с `{2180100}`. Значит, движок FH4 штатно выбирает весь набор моделей кузова по ID тела. У 3477 уже есть своя строка `List_UpgradeCarBody` с Id и CarBodyID 3477000, а у Acura type 2 фиксированная (71 модель). Phase 3.3 подтвердила, что новая Modelbin внутри общего ZIP рендерится, если правильно привязать её по ID и поправить `0x1123`.

## Что остаётся общим с 368 при варианте B

Эти данные задаются один раз на MediaName и по ID не выбираются:

- `scene/*_skeleton` и `Locators.xml`: точки колёс, фар, выхлопа, камер. У DC2 JDM база 2.545 м. Шасси то же, что у Acura DC2, поэтому посадка, скорее всего, совпадёт, но это нужно проверить.
- `Lights.bin` и `LightPresets.bin`: позиции и форма световых зон.
- `physicsdefinition.bin`: коллизия и повреждения, `aovolumetexture.bin`.
- Анимации `.gr2` (двери, капот, багажник, стрелки), `IKAnchorBones.xml` и `.avpins`. У JDM DC2 правый руль, у Acura левый. Правый руль сделать нельзя: салон надо оставить леворульным или зеркалить.
- Type 43 (колёса) и type 4 (тормоза) нигде в FH4 не апгрейдные. Стоковый диск 3477 можно сменить на существующий диск из `_library/scene/wheels` через строки rims в БД. Новый диск FM4 потребует нового архива и записи в манифесте, а эта ветка не проверена.
- Звук, Forzavista, миниатюра и XAML уже общие с 368 (Phase 1–2).

## Ограничения исходника FM4

- carbin-garage даёт main, LOD0 и cockpit (120 мешей), 10 текстур XDS→PNG и 49 материалов. FH4 нужны LOD0–LOD5 плюс shadow (LODS) на каждую Modelbin. Modelbin Creator умеет размножать меши по LOD.
- В FM4 двери, скорее всего, вшиты в `body`, поэтому анимация дверей FH4 и Forzavista получат либо пустые двери, либо двери Acura.
- Материалы FM4 надо вручную сопоставить с материалами FH4 из `_library/materials` (`carpaint`, стекло, хром, фары). Текстуры фар и салона переводятся в PC swatchbin через Swatchbin Creation в ForzaTech Studio. Вариант Durango там не поддерживается, для Steam он не нужен.
- Деформация повреждений (morph) не переносится, геометрия будет без визуальных повреждений.
- Кокпит FM4 — упрощённый салон: нет отдельного пола, торпедо и консоли как в FH4. Приборы FM4 сделаны иначе.

## Риски

- Донор 368 затрагивается неизбежно: меняется общий Carbin (fixed type 2 → upgrade group), а 368000 надо внести во все shared-списки. Ошибка ломает обе машины. Откат возможен только восстановлением Phase 2 ZIP и манифеста; скрипты для этого есть.
- Сохранение: в профиле 3477 записан стоковый кузов 3477000, это совпадает с нужным ID. Тесты вести только на копии офлайн-профиля, как раньше.
- Пересчёт ZIP: каждая новая запись требует правильного `0x1123`, а манифест — новых `dirstart/dirsize/direntries`. Иначе будет падение `0xC0000005` (Phase 3.3 `bind`).
- Мультиплеер и онлайн исключены: изменённые ZIP и БД допустимы только в офлайн-копии.

## Предлагаемый порядок проверки (каждый шаг с откатом)

1. **Контроль type 2.** Перевести type 2 Acura в upgrade group с узлами 368000 и 3477000, оставив обоим ID все 71 исходную модель. Ожидается, что обе машины выглядят как в Phase 2. Это главный неизвестный шаг. Если он падает, вариант B ограничивается группами 34, 35, 36, 37 и 9.
2. **Клон одной модели.** Привязать скопированную `body_a.modelbin` только к 3477000, а 368000 оставить на оригинале, плюс A/B-изменение геометрии, как в Phase 3.3.
3. **Первая Modelbin из Creator.** Поставить простой меш FM4 (`bumperFa` LOD0) в группу 34, где привязка уже доказана, чтобы проверить формат Creator для FH4.
4. **Поэтапный перенос.** Кузов, затем стёкла и фары, затем бамперы, капот, пороги, крыло, затем салон. Скрывать модели Acura для 3477 (дверные ручки, зеркала и т.п.), удаляя 3477000 из их списков.
